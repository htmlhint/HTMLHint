import { Badge } from '@astrojs/starlight/components';

The `<script>` tag can not be used in head.

Level: <Badge text="Warning" variant="caution" />

## Config value

- `true`: enable rule (disallow all scripts in head)
- `false`: disable rule
- `"allow-non-blocking"`: allow non-blocking scripts (modules, deferred, and async scripts) in head

### The following patterns are **not** considered rule violations

#### Default behavior (`true`)

```html
<body>
  <script src="test.js"></script>
</body>
```

```html
<head>
  <script type="text/template">
    <div>Template content</div>
  </script>
</head>
```

#### With `"allow-non-blocking"` option

```html
<head>
  <script type="module" src="module.js"></script>
</head>
```

```html
<head>
  <script defer src="deferred.js"></script>
</head>
```

```html
<head>
  <script async src="analytics.js"></script>
</head>
```

```html
<head>
  <script type="module">
    import { init } from './app.js';
    init();
  </script>
</head>
```

### The following patterns are considered rule violations

#### Default behavior (`true`)

```html
<head>
  <script src="test.js"></script>
</head>
```

```html
<head>
  <script type="module" src="module.js"></script>
</head>
```

#### With `"allow-non-blocking"` option

```html
<head>
  <script src="test.js"></script>
</head>
```

```html
<head>
  <script type="text/javascript">
    console.log('blocking script');
  </script>
</head>
```

## Why this rule is important

Scripts in the `<head>` section affect HTML parsing differently depending on their attributes. A classic external script without `async` or `defer` pauses parsing while the browser fetches and executes it. The external `defer`, `async`, and module forms shown above let parsing continue while resources are fetched, but they provide different execution-order and DOM-readiness guarantees.

| Script form                           | Parsing and execution                                                                     | Ordering and DOM readiness                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `<script src="app.js">`               | Pauses parsing while the script is fetched and executed                                   | Preserves document order; elements after the script are not available yet                                   |
| `<script defer src="app.js">`         | Fetches in parallel and executes after parsing, before `DOMContentLoaded`                 | Preserves document order; `DOMContentLoaded` waits for execution                                            |
| `<script async src="app.js">`         | Fetches in parallel and executes as soon as it is ready, potentially interrupting parsing | Does not preserve document order; later DOM elements might not exist, and `DOMContentLoaded` does not wait  |
| `<script type="module" src="app.js">` | Fetches the module graph in parallel and executes after parsing by default                | Preserves document order by default; `DOMContentLoaded` waits, while `async` removes the ordering guarantee |

Non-blocking fetching does not mean zero performance cost. Downloading, compiling, and executing a script can still consume network bandwidth and main-thread time.

For more information, see:

- [MDN: Script element](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script)
- [MDN: defer attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script#defer)
- [MDN: async attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script#async)
- [MDN: JavaScript modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)
